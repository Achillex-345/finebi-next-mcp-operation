# finebi-next-mcp-operation · FineBI Next MCP 操作 Skill

**当前版本：V0.2**（2026-10-30，内部迭代 0.24.0）

这是给 AI 助手（Claude Code / Codex）用的一套**行为规范**：AI 用 FineBI Next MCP 做分析时，先想什么、数据怎么建模、表怎么拆、什么时候建指标。规则都来自真实项目里反复让 AI 搭看板、出错、修正的过程，每条都有原因和案例。

## 这份规范解决什么问题

AI 直接生成分析资产时，常见的结果是**表拆得很碎、结构很乱**：
- 一张图建一张表，一个指标建一张中间表；
- 比率、达成率算好存进表里，上卷后被求和或求平均；
- 先把明细关联起来再汇总，数据扇出，数字被放大；
- 同一个口径在好几个地方各写一遍，改的时候漏改。

后果是组件之间不同源、联动断掉、口径对不上，人也看不懂结构。

这份 Skill 用三层顺序和一组判断规则约束 AI：**先想清楚业务，再定数据结构，最后才写 DSL**；每建一张表、每算一个数，都要能说清它属于哪一层、为什么放在这一层。

建议重点看第一到第五节和第七节：可以直接用来改产品内 AI 的规划步骤和提示词。

## 一、三层：先业务、再建模、最后写 DSL

| 层 | 回答什么 | 稳定性 | 文档 |
|---|---|---|---|
| 业务设计 | 看什么指标、凭什么判断好坏、往哪里拆、怎么解释原因 | 不随工具变 | [`business-design.md`](finebi-next-mcp-operation/references/business-design.md) |
| 建模设计 | 数据怎么组织，才撑得住上面的判断 | 不随工具变 | [`dashboard-architecture.md`](finebi-next-mcp-operation/references/dashboard-architecture.md)、[`modeling-method.md`](finebi-next-mcp-operation/references/modeling-method.md) |
| DSL 写法 | 在当前工具里具体怎么写 | 随版本变 | 现查 MCP Help；Skill 只记谬误 |

**业务设计是一条推导链**，每一步由上一步推出：

1. **指标**：先定结果指标和它的构成，如 量 × 转化率 × 单值 = 结果。
2. **判断逻辑**：数字要有参照才有好坏：和目标比（达成率）、和上期比（环比）、和去年比（同比）。
3. **时间切片**：有同环比就要先定义“本期”，对比期由本期推出。
4. **维度切分**：按组织、对象拆开，看谁拉动、谁拖累。
5. **历史趋势**：一张不随切片变的长期趋势图，判断是持续走势还是一次性波动。
6. **业务归因**：从结果视角转到过程视角（来源、品项等），解释原因。

**新需求的工作流**：先给业务设计 → 再给建模设计和“计划态结构图”（源表 → 分析表 → 分支 → 图表 → 指标，标出新增 / 改动 / 删除）→ 用户确认这两样 → 才写资产。结构图画法见 [`structure-map.md`](finebi-next-mcp-operation/references/structure-map.md)。

## 二、拆表：什么时候建表，什么时候不建

**总原则**：越多组件复用、越接近原子事实的，越靠近主宽表；越专用的，越靠近图表。主宽表保持同源，组件之间就能天然联动，不需要任何配置。

**分层**（每层只做一件事）：

```
原始表    导入即用，不改
中间表    每张只把一个来源规整成“可关联的键 + 粒度”：名单、分摊后的目标、对象静态属性、过程打卡
输出表    主宽表（骨架）+ 子业务宽表；看板只挂输出表
图表分支  只服务一张图：按参数分期汇总、换到展示粒度
指标      在展示粒度上重算的比率与对比
```

**每样东西放哪一层**：

| 判断 | 放哪 |
|---|---|
| 逐行可算的原子字段、标签、时间粒度字段 | 主宽表 |
| 跨表关联、分区极值（子查询 groupBy + join） | 主宽表 |
| 换粒度（如每个对象一行），且**多张图**要用 | 独立的子业务宽表 |
| 换粒度或专用加工，但**只有一张图**用 | 图表分支（高级模式步骤），不建表 |
| 图上分组、聚合就能出结果 | 图表直接挂主宽表 |
| 合计、比率等业务指标 | 指标，不落表 |

**只有这几种情况才新建表**，AI 新建表前必须说明属于哪一种，说不出就不建：

1. **中间表**：一个来源要先规整成可关联的键和粒度。一个来源一张，口径变了只改一处；中间表不算业务比率。
2. **主宽表（骨架）**：看板要用到的最细公共粒度，通常一个看板一张。
3. **子业务宽表**：某个维度加进主宽表会让行数扇出（如来源、品项），或换粒度后有多张图共用。
4. **目标对比表**：目标粒度比明细粗、只按整年或整月对比时，以目标表为主表单独建一张（见第五节）。

## 三、主宽表怎么搭：骨架宽表

适用于“多个业务事实 + 目标 + 组织层级 + 同环比”的经营类看板：

1. **骨架粒度** = 最细公共粒度，通常是“组织末级对象 × 日”。日是最细时间单位，任意区间、周、月都能从日聚合。
2. **每个事实各自汇总到骨架粒度，再合并**。每个事实用自己的业务时间（如线索按创建时间、成交按成交日期）。**不要先关联明细再汇总**：会扇出，也会把两种时间口径混在一起。
3. **全外连接，键取齐**：日期加组织各层级字段都作为连接键，避免一侧为空的行丢掉上级字段。
4. **按对象补齐日期**：每个对象每天一行。任意区间可以直接求和，按日摊开的目标不会丢，“去年同日”一定取得到。
5. **其他数据按各自粒度左关联**：分类标签（对象级）、目标（对象 × 月）、静态属性、过程数据。关联前确认右表在键上唯一，否则骨架扇出、所有量被放大。
6. **分类标签留在表里，范围交给筛选器**：不按标签删数据、不为两类对象各建一套表；默认范围由看板筛选器的默认值限定。

## 四、指标：什么时候建指标

**表里只存可加的原子量**（计数、金额、目标量）。比率、均值、达成率一律在展示粒度上用 Σ分子 / Σ分母 重算，不存行级比率，也不对比率求和或求平均。

| 要算的东西 | 用什么 |
|---|---|
| 逐行可算的字段、分类标签 | 表里的公式字段 |
| 合计、比率、达成率 | 指标 `.metric("<名>", "SUM([<分子>])/SUM([<分母>])")`，在每个展示粒度自动重算 |
| 指标公式写不出的（条件聚合、日期差、要引用参数的） | 图表分支里先聚合计算、再聚合后计算 |
| 受日期控件控制的同环比 | 控件绑开始 / 结束参数，分支按本期、环期、同期分别聚合，指标算比值 |
| 占比、排名、累计 | 快速计算（待实测） |

指标体系的几条要求：
- **用指标链组织**：结果 = 量 × 转化比率 × 单值，每个比率的分母取链上前一环；指标卡按链从左到右排列。
- **对比口径**：量的同环比用增长率，比率的同环比用百分点差，并在名称里标明。
- **分母为 0 时结果为空**，不写成 0；均值的分母用去重对象数，不用行数。
- **同一口径出现在多处时公式逐字一致**；改口径前先列出所有引用位置。

## 五、目标与实际

- **有日骨架、要按任意日期区间看达成**：月目标在中间表里按当月天数摊到日，挂在骨架上；达成率的分子只累计“有目标的对象 × 日”，分母分子同范围，否则达成率虚高。没有目标时达成率为空。
- **目标粒度粗、只按整年或整月对比**：以目标表为主表；实际先按目标粒度汇总，再左关联（不要把目标挂到明细上，会被重复加总）；上级维度直接放进汇总的分组里，不再做一次映射关联；无实际记 0；达成率用指标，需要逐级看时用组件内下钻。

## 六、时间对比：两类组件分开设计

| 类型 | 典型组件 | 时间控制 |
|---|---|---|
| 区间对比组件 | 指标卡、组织交叉表、对象排行 | 跟随看板日期区间：区间控件绑**参数**，分支里按本期 / 环期（等长、紧挨本期）/ 同期分别聚合 |
| 趋势组件 | 近 N 个月趋势图 | 固定滚动窗口，不跟随日期区间 |

日期区间控件不绑字段：字段筛选在汇总前生效，会把环期、同期的数据一起筛掉。

## 七、典型的“表拆碎了”与正确做法

| AI 常见做法 | 问题 | 本规范的做法 |
|---|---|---|
| 每张图单独建一张表 | 组件不同源，联动断掉，结构难懂 | 同源主宽表；只有一张图用的加工放图表分支 |
| 为一个指标建一张中间表，并存行级比率 | 比率上卷被求和或平均，数字错 | 原子量入表，比率用指标在展示粒度重算 |
| 先关联明细再汇总 | 扇出，数字被放大；时间口径混在一起 | 各事实先汇总到骨架粒度，再全外连接 |
| 目标对比建两张中间表，还多做一次维度映射关联 | 结构冗余，目标被重复加总 | 一张表：目标为主表，实际汇总后左关联，上级维度随分组带出 |
| 为两类对象各建一套表 | 同一套资产不能切换分析范围 | 标签留表，范围交给筛选器默认值 |
| 把会扇出的维度直接加进主宽表 | 所有量被放大 | 另建子业务宽表，带上与主宽表同名的组织字段和标签（一致维度），筛选和联动照样能用 |
| 用窗口 min/max 求每个对象的首单时间 | 平台自动补排序，变成累计值，全错且不报错 | 子查询 groupBy 求极值，再 join 回来 |
| 在图表分支里用公式造合计 | 指标和数据处理混在一起 | 合计、比率一律用指标 |

## 八、怎么用来优化产品内 AI

几条可以直接落地的做法：
1. **规划先于生成**：让 Agent 先输出业务设计和计划态结构图，再写资产（第一节）。
2. **建表要说明属于哪一类**：中间表 / 主宽表 / 子业务宽表 / 目标对比表，说不出就不建（第二节）。
3. **比率不落表**：写入前检查表里有没有比率、均值字段（第四节）。
4. **关联前查唯一性**：左关联前确认右表在键上唯一，避免扇出（第三节）。
5. **把校验规则前置**：[`scripts/lint_chart_dsl.mjs`](finebi-next-mcp-operation/scripts/lint_chart_dsl.mjs) 的 13 条规则是 AI 最常写错的 DSL，可以放到写入前校验。
6. **用评测集回归**：[`evals/anchors.md`](finebi-next-mcp-operation/evals/anchors.md) 的 21 个场景都有提示词和预期要点。
