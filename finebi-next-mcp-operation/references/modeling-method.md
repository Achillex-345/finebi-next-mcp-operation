# 经营看板建模方法：骨架宽表、指标体系、时间对比

适用于“多个业务事实 + 目标 + 组织层级 + 同环比”的经营类看板。本文属于建模层：业务上为什么要这些组件，见 `business-design.md`；`dashboard-architecture.md` 回答“放哪一层”，本文回答“这一层怎么搭”。DSL 写法以当时的 Help 和校验为准，这里只写方法（D-039 ~ D-042）。

## 目录

- 一、分层：每层只做一件事
- 二、主宽表：选骨架粒度，事实各自汇总再合并
- 三、目标：摊到骨架粒度，挂在骨架上
- 四、对象分类：标签留在表里，范围交给筛选器
- 五、指标体系：原子量入表，比率按链重算
- 六、时间对比：区间组件与趋势组件分开设计
- 七、子业务宽表：换粒度另建表，维度保持一致
- 八、看板组织与交互
- 九、看板说明书：让 AI 能用看板复盘

## 一、分层：每层只做一件事

```
原始表   ← 导入即用，不改
中间表   ← 每张只把一个来源规整成“可关联的键 + 粒度”：名单、分摊后的目标、对象静态属性、过程打卡
输出表   ← 主宽表（骨架）+ 子业务宽表；看板只挂输出表
图表分支 ← 只服务一张图：按参数分期汇总、换到展示粒度
指标     ← 在展示粒度上重算的比率与对比
```

- 中间表不算业务比率，只做清洗、分类、汇总到关联粒度。一个来源一张，口径变了只改一处。
- 抽查用的调试步骤（如末尾按单个对象过滤）留在表里并禁用，需要核对时临时启用，不影响下游。

## 二、主宽表：选骨架粒度，事实各自汇总再合并

1. **骨架粒度** = 看板要用到的最细公共粒度，通常是“组织末级对象 × 日”。日是最细时间单位，任意日期区间、周、月都能从日聚合。
2. **每个事实各自汇总到骨架粒度，再合并**。每个事实用自己的业务时间（如线索按创建时间、成交按成交日期），不要先关联明细再汇总：明细关联会扇出，也会把两种时间口径混成一个。
3. **全外连接，键取齐**：日期加上组织各层级字段都作为连接键。只用末级键时，一侧为空的行会丢掉上级层级字段。
4. **按对象补齐日期**：保证每个对象每天一行。好处有三个：任意区间都能直接求和；按日摊开的目标不会因为当天没有业务而丢失；“去年同日”一定取得到。
5. **其他数据按各自粒度左关联到骨架**：对象分类标签（对象级）、分摊后的目标（对象 × 月）、静态属性（对象级）、过程数据（对象 × 日）。关联前确认右表在关联键上唯一，否则骨架行会扇出、所有量被放大。
6. **时间窗口**：只保留“最长展示期 + 同期所需”的范围（如近两年），控制体量。
7. **范围口径放在最后一步**（如只保留某类组织）。哪些输出表没有套用这一步要明确记录，写进口径说明。

## 三、目标：摊到骨架粒度，挂在骨架上

- 月度目标在中间表里按当月天数摊成日目标，再按“对象 + 年月”关联到骨架。因为骨架已补齐日期，任意日期区间的目标 = 区间内日目标之和。
- 比率型目标（如单值、比率目标）不能按天摊，保持原值，只作对照，不参与求和。
- **达成率的分子和分母取同一范围**：分子只累计“有目标的对象 × 日”的实际值。否则无目标的月份或对象只进分子，达成率虚高。同一看板里指标卡、交叉表、趋势图的达成率要用同一口径。
- 没有目标时达成率为空，不是 0。
- 和 D-033 的分工：看板按任意日期区间看达成，且已有日骨架时，用本节做法；目标粒度粗、只按年或月整期对比时，用 D-033 的独立对比表（以目标表为主表）。

## 四、对象分类：标签留在表里，范围交给筛选器

- 对象分类（如“是否纳入考核名单”）从名单或目标表派生成标签列，左关联到**每一张**输出表。未命中的对象保留，标签为空。
- 不在表里按标签删数据：同一套资产要能分析两类对象。范围由看板筛选器加默认值限定。
- 默认值是隐含前提：在看板副标题、口径说明和说明书里写明，并说明分析另一类对象时先清空该筛选。
- 标签依赖哪张名单、名单按什么规则生成（如“有目标即纳入”），写进口径说明，方便判断某个对象属于哪类。

## 五、指标体系：原子量入表，比率按链重算

1. **表里只存可加的原子量**：计数、金额、目标量。比率、均值、达成率一律在展示粒度上用 Σ分子 / Σ分母 重算，不存行级比率，也不对比率求和或求平均。
2. **用指标链组织指标**：把结果指标拆成乘积链，如 结果 = 量 × 转化比率 × 单值。每个比率的分母取链上的前一环，链上恒等式才成立。指标卡从左到右按链排列，分析也沿链拆解结果的变化来自哪一环。
3. **对比口径**：量的同环比用增长率；比率的同环比用百分点差，并在名称里标明。
4. **分母为 0 时结果为空**，不要写成 0，避免在排名和着色里被当成最差值。
5. **均值类**（如每对象平均）= Σ量 / 去重对象数，对象数用去重计数，不用行数。
6. **单位**：原子量保留源单位，换算放在展示层。目标与实际单位不同时显式换算，并在名称里标出单位。
7. **可下钻的表**：分支先汇总到最细对象粒度（保留对象键），指标在每一层重算，这样每层都对。合计行对比率的处理平台不一定正确，以指标卡为准。
8. **同一口径出现在多处**（指标卡、交叉表、排行）时，公式逐字一致；改口径前先列出所有引用位置。

## 六、时间对比：区间组件与趋势组件分开设计

先把每个组件归成两类，并在区块副标题写明：

| 类型 | 典型组件 | 时间控制 |
|---|---|---|
| 区间对比组件 | 指标卡、组织交叉表、对象排行、结构对比条形图 | 跟随看板日期区间 |
| 趋势组件 | 近 N 个月柱线图 | 固定滚动窗口（相对今天），不跟随日期区间 |

**区间对比组件**

1. 日期区间控件绑**参数**（开始、结束），不绑字段：字段筛选在汇总前生效，会把环期、同期的数据一起筛掉（D-025 的区间版）。
2. 在同一个分支里按三期条件聚合：
   - 本期：[开始, 结束]；
   - 环期：紧挨着本期之前、长度相同的区间 [开始 − N, 开始 − 1]，**N = 结束 − 开始 + 1**（漏掉 +1 会让环期少一天，选单日时环期为空）；
   - 同期：整体往前平移一年。
3. “往前一年”只选一种定义（固定 365 天，或去年同日），全看板统一，并写进口径说明。
4. 比率的对比：先分别算出各期比率，再相减。

**趋势组件**

1. 窗口用相对今天的滚动区间（如近 12 个完整月加当月），写在标题里。
2. 同期的取法看表有没有补齐日期：
   - 补齐了的骨架表：用“取去年同日”的同期计算。
   - 没补齐的表（带业务维度的子表，无法逐日补齐）：把去年的行整体平移一年，与今年的行合并后一起汇总。直接按日取同期，会漏掉“今年当天没数据”的键，同期偏小。
3. 同比 = Σ本期 / Σ同期 − 1，作为指标在图上重算。

参数只能在分支步骤里使用，指标公式里不能引用参数（K-29）。需要按参数切换指标时，在分支里按参数取值，指标只写一个。

## 七、子业务宽表：换粒度另建表，维度保持一致

1. 某个分析维度会让骨架行扇出（如来源、品项）时，不加进主宽表，另建“骨架粒度 × 该维度”的输出表。
2. **一致维度**：子表带上与主宽表同名的组织层级字段、对象键和分类标签。全局筛选器靠同名字段绑定，跨表联动靠同名字段映射；缺一个，新板块就筛不动。新建子表或把新图放进看板前，逐项核对。
3. 子表合并多个事实时，同样先各自汇总再全外连接。连接键里有可能为空的维度时，合并后要按键再收敛一次，避免同一键出现两行。
4. 子表与主宽表的范围差异（是否套用范围口径、时间口径）是有意的决定，写进口径说明，并提醒“子板块的量可能大于主指标”。

## 八、看板组织与交互

1. **区块按业务推导链排**（business-design.md）：结果指标卡 → 维度拆解（组织交叉表下钻 + 对象排行）与趋势 → 归因板块 → 口径说明。
2. **全局筛选区**：分类范围（带默认值，绑字段）、组织层级下拉（绑字段，控制全部组件）、日期区间（绑参数，只驱动区间对比组件）。
3. **三种联动各管一段**：
   - 主宽表上的组件之间天然联动；
   - 子表板块用跨表联动接收组织最上层和对象键；
   - 层级用组件内下钻。下钻出来的层级不能作为联动源，所以下级组织的板块筛选交给全局筛选器。
4. 每个区块的副标题写明是否受日期区间控制、数据范围是否与主指标不同。

## 九、看板说明书：让 AI 能用看板复盘

看板定稿后，可以用故事板写一份说明书，作为生成“复盘 / 分析 Skill”的底稿：

1. 输入映射：用户说的分析范围（时间、组织、对象）对应哪些筛选器、怎么设。
2. 对象分类判定：如何在看板上判断对象属于哪一类，以及判定结果决定分析什么（有目标才评价达成）。
3. 组件说明：每个组件回答什么问题、受哪些控件控制、指标链关系。
4. 联动与钻取表，以及限制和绕行办法。
5. 分析步骤：确认范围 → 分类判定 → 结果指标 → 下级拆解 → 趋势 → 链上各环节的结构 → 写报告。
6. 报告模板：结论摘要、指标表、变化拆解、问题与建议；每个数字都要能在看板上找到出处。
7. 口径与注意事项：时间口径、范围差异、已知缺陷、异常值，以及 MCP 读取看板时参数不生效等平台限制（K-18）。
