# 看板视觉方法

审美是对场景的判断，不是一套固定风格（D-037）。本文件只规定**不变的底线**和**怎么按场景定方向**；具体风格在 `visual-directions.md` 的方向库里，每次按场景选，不设默认项。

## 分工：方法、方向、项目档案

| 层 | 放在哪 | 内容 | 变化频率 |
|---|---|---|---|
| 方法与底线 | 本文件 | 流程、底线、自评 | 很少变 |
| 方向库 | `visual-directions.md` | 可选的视觉方向，每个写清适合 / 不适合的场景与手法 | 验证一个加一个 |
| 项目视觉档案 | 演示 / 客户项目目录下的 `视觉档案.md` | 本项目的场景评估、选定方向、色板、标志性元素、用户确认过的偏好 | 每个项目一份 |

用户确认过的偏好（如“不要圆角”“组件融入页面”）记入项目视觉档案，优先于方向手法；跨项目反复出现的偏好再提炼进方向库或底线。

## 先判断范围：扩展还是新建

- **扩展**（在已有看板上加板块、加图、改一张图）：沿用项目视觉档案里的方向和色板，不重新选方向；新元素按已有区块的样式做。
- **新建或整体改版**：走下面的场景评估和选方向。
- 没有项目视觉档案的已有看板：先从现有 Markup 和图表配色反推出它的方向，写成档案，再按“扩展”处理；用户要求改版时才重新选。

## 场景评估

开做前写四行，记入项目视觉档案：

1. **受众与场合**：谁、在什么场合看（会上投屏讲、每天自己看、值守大屏、发给客户），看多久。
2. **一个问题**：这张看板首先回答的那个问题，一句话（如“本月经营是否达标，差在哪”）。
3. **一个发现**：当前 READY 数据里最需要被注意的事实（如“今年首次未完成目标”）。
4. **业务对象**：这个场景独有的对象和行话（门店、班次、合同、子类别目标……），标志性元素从这里来。

信息来源：项目上下文、用户原话、数据本身（`get_project_asset_details` 回读）。缺失时按最可能的场景假设并在交付说明里写出假设，不为此打断用户。

## 选方向：自己定，不出选项

1. 在 `visual-directions.md` 里按场景评估逐项对照“适合 / 不适合”，内部列出至少三个候选（含“行业标准版”）。
2. **防收敛自查**：只凭“这是一张 <行业> 看板”就能猜到的方向，是品类默认；除非场景明确需要，不选它。上一个项目刚用过的方向，换场景时不沿用。
3. 选定一个，直接做。**不把候选摆给用户挑**；只有用户明确要求比稿、多版对比时才做多版（D-037）。
4. 给方向一张“脸”，两项都要有：
   - **标志性元素**：一个只属于这个业务的图或区块，由业务对象做成（如按子类别的目标子弹条、门店分布、班次覆盖矩阵）。
   - **主数据色**：方向色板里唯一的数据色放在回答问题的那个系列上；客户有品牌色时用品牌色替换它。

## 按问题排区块

- **最大的区块回答“一个问题”**；最大的数字也是它。
- 其余区块各回答一个后续问题（“差在哪”“谁贡献的”“明细是谁”），每块一行写下它回答什么；回答不了问题的区块删掉。
- “一个发现”放在最先读到的位置：页副标题或最大区块的标题。
- 区块顺序、宽度比例、是否要指标卡行，都由问题决定，不套固定骨架。几个数字就能回答的，不画图。

## 底线（任何方向都遵守）

**颜色**
- 状态色表达好坏，不表达涨跌：越低越好的指标（成本、退货率、时长）下降为好；零变化、无法比较显示灰色或“—”。
- 状态色只用于好坏，配箭头或文字；不拿来当类别色。
- 每张图最多一个主色系列，其余灰或浅色；全页数据色相不超过 3 个（状态色另计）。
- 多类别必须区分时用同色系深浅，不用彩虹色。

**图形**
- 柱为直角，系列不描边；单系列不放图例。
- 对比值写明窗口：“较上月”“较去年同月”“较目标”。
- 标题里的结论来自 READY 数字；结论可能随筛选失效时，注明数据范围（如“全量数据”），或写成不含具体数字的定性表述。

**Markup**
- 文本显式写 `font-weight`（K-21）；改版现有看板沿用全部原 id（D-035）；容器高度包含 padding。
- 写法与坑见 `chart-dsl.md`「带对比与状态的指标卡」「迷你趋势」「灰作背景、主色高亮、RAG 参考线」「数字格式」，以及 `dashboard.md`。

## 自评

在「预览」中等动画结束（约 20 秒）后截图，逐项过：

- [ ] 底线全部满足；指标卡对比行未被截断。
- [ ] 最大区块回答了“一个问题”；“一个发现”在最先读到的位置。
- [ ] **遮住标题和数据，换一个行业还能直接用吗？** 能，就说明没有脸：补标志性元素或把主数据色放到位。
- [ ] 每个区块都能说出它回答的问题。
- [ ] 符合项目视觉档案里用户确认过的偏好。

不过的项改完再交付；自评结论一并写进项目视觉档案。

## 交付与调整

- 交付时一句话说明：按什么场景判断、选了哪个方向、标志性元素是什么、做了哪些假设。
- 用户的调整用方向内的动词处理，不重新选方向：

| 用户说 | 怎么改 |
|---|---|
| 安静一点 | 降低饱和度，去掉次要强调，减少状态色以外的颜色 |
| 大胆一点 | 主数据色面积加大，最大区块更大，标题字号拉开层级 |
| 精简 | 删掉回答不了问题的区块和重复数字 |
| 加点颜色 | 主数据色扩展到同色系的第二层级，或给分节加色 |
| 更密 / 更松 | 调整区块间距、内边距和每行区块数 |

- 用户明确说“换个风格”，才回到「选方向」，并把被否定的方向记进项目视觉档案。
