# 看板体系：宽表 → 分支 → 图表 → 指标 → 交互

用户给出的目标架构（D-029），以及每一层“什么时候用”的判断规则。状态列区分已验证与目标能力；目标能力上线前按“现阶段做法”执行。

## 架构总览

```
分析表（主宽表）                        ← 原子字段、行级标签、关联、时间字段；所有组件同源
 ├─ 高级模式：子业务宽表（分支）          ← 换粒度的数据集，可服务多张图（目标）
 │    ├─ 图表 A ── 快速计算（占比 / 排名 / 累计 / 同环比）
 │    │        └─ 聚合指标 ──共享──► 图表 B（目标）
 │    └─ 图表 B
 ├─ 高级模式：过程处理（分支）            ← 只服务一张图的加工
 │    └─ 图表 C
 └─ 图表 D（直接挂宽表）                  ← 图上分组聚合即可

指标库 / 计算模型（独立）                 ← 跨图、跨表复用的口径中心（目标）
```

## 一、数据放哪一层

| 判断 | 放哪 | 状态 |
|---|---|---|
| 逐行可算的原子字段、标签、时间粒度字段（如 `COMBINE(<日期>,'YM')`） | 主宽表（`upsert_tables`） | 已验证 |
| 跨表关联、分区极值（子查询 groupBy + join，见 D-024） | 主宽表 | 已验证 |
| 换粒度（如每个对象一行）且多张图要用 | 子业务宽表分支；现阶段一分支只能挂一张图，多图共用时提升为独立分析表 | 已验证：独立子表带上与主宽表同名的组织字段和分类标签后，全局筛选器可绑定、跨表联动可映射（modeling-method.md 七） |
| 只为一张图服务的加工（专用筛选、按参数分期汇总） | 过程处理分支（图表 query） | 已验证 |
| 图上分组、聚合即可出结果 | 图表直接挂主宽表 | 已验证 |

原则：**越多组件复用、越接近原子事实的，越靠近主宽表**；越专用的，越靠近图表。主宽表保持同源，是联动免费的前提（D-023）。

## 二、计算放哪一层

| 判断 | 用什么 | 状态 |
|---|---|---|
| 合计、比率等业务指标 | 聚合指标 `.metric("<指标名>", "<聚合公式>")` | 已验证（单图内） |
| 占比、排名、累计 | 快速计算 `CalculationType.PERCENT / RANK_* / ACCUMULATE` | Help 有写法，待实测 |
| 同环比，且图上有时间轴 | 快速计算（目标）；现阶段在分支取同期：补齐日期的表用去年同日，未补齐的表把去年行平移一年后合并汇总；同比用指标 | 已验证（modeling-method.md 六） |
| 同环比，但组件是单值且受月份筛选（指标卡） | 参数 + 过程处理分支分期汇总 + 指标算比值（D-025） | 已验证 |
| 同环比，组件受任意日期区间控制 | 区间绑开始、结束两个参数；分支按本期 / 等长环期 / 同期条件聚合 | 已验证（modeling-method.md 六） |
| 指标公式写不出（条件聚合、日期差、日期型结果） | 分支的聚合计算 / 聚合后计算（D-019） | 已验证 |

## 三、交互用什么

| 场景 | 用什么 | 状态 |
|---|---|---|
| 临时探索“看某一类 / 某一期” | 同源组件点击联动，零配置 | 已验证 |
| 常驻条件、默认值、条件字段不在图上、跨表统一过滤 | 筛选器绑字段 + 控制范围 | 已验证 |
| 选择值不能过滤数据（对比期、阈值、口径切换） | 筛选器绑参数，由引用参数的分支计算 | 已验证 |
| 某组件不应受控（如长周期趋势） | 不纳入控制范围、不引用参数 | 已验证 |
| 一个控件同时驱动两类组件 | 同时绑参数（驱动指标卡）+ 绑字段（控制其余图），控制范围排除参数驱动的组件 | 已验证 |

## 四、目标能力与现阶段做法

| 目标能力 | 现阶段做法 | 代价 |
|---|---|---|
| 指标跨图共享 | 每张图各写一遍相同 `.metric`，名称与公式保持逐字一致 | 改口径要改多处；改前列出所有引用该口径的图 |
| 指标库 / 计算模型 | 未使用；Query 有 `.computeModelRef(...)` 引用写法，MCP 无创建工具 | 待验证 |
| 一个分支挂多张图 | 多图共用的粒度提升为独立分析表；只一张图用时留在分支 | 新表不同源，不会天然联动；需要时配跨表联动（dashboard.md） |
| 同环比快速计算 | 分支 `periodOverPeriod` 或参数分期 | 写法较重 |

## 五、设计顺序

1. 先列出看板要回答的问题与组件清单，标出每个组件的粒度。
2. 主宽表补齐所有原子字段（标签、时间粒度、关联字段）。多事实合并、目标挂载、日期补齐的做法见 modeling-method.md 二、三。
3. 按“一、数据放哪一层”决定每个组件挂主宽表、分支还是独立分析表。
4. 按“二、计算放哪一层”决定指标、快速计算、分支计算。
5. 按“三、交互用什么”决定联动、筛选器、参数与控制范围。
6. 组件全部回读 READY 后再排版看板；必须界面操作的配置放最后（D-026），之后在 AI 副本上继续协作（D-028）。

## 六、目标与实际对比建模（D-033）

目标、预算、计划表的粒度通常粗于明细（如 <维度> × 年）。本节适用于按整年、整月对比；看板要按任意日期区间看达成、且主宽表已有逐日骨架时，改用“目标摊到日、挂在骨架上”（modeling-method.md 三）。

1. **以目标表为主表**：只统计有目标的范围；没有目标的期间不进入达成率。
2. **实际先汇总再关联**：子查询把实际按目标粒度 `groupBy` 汇总后左关联；不要把目标挂到明细上，否则目标会被每行重复加总。
3. **维度属性随分组带出**：上级维度与关联键一对一时，直接放进汇总子查询的 groupBy，不另做一次映射关联。
4. **无实际记 0**：`.formula("NVL([<实际>], 0)").as("<实际>")`。
5. **实际取自主宽表**：与看板其他组件同一口径，不从源表重算。
6. **比率不落表**：达成率、差额用指标 `SUM([<实际>])/SUM([<目标>])`；需要逐级看时用组件内下钻 `.drill(dim("<一级>"), dim("<二级>"), …)`，每层按指标重算。
7. **交互**：对比表与主宽表不同源，不会天然联动；需要联动时配跨表联动，月份类筛选器的控制范围排除按年对比的图。
