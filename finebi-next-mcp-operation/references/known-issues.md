# 平台已知问题与环境限制

记录 FineBI Next MCP 的缺陷和租户限制，不是操作规则。每条写明发现日期，修复后标注“已修复”而不是删除。

| 编号 | 现象 | 影响 | 应对 | 发现 |
|---|---|---|---|---|
| K-01 | UI 删除的项目仍出现在 `list_projects`，且资产可完整读取 | 可能读写到已删项目 | 以用户界面为准，按名称确认目标项目；不对用户未点名的项目写入 | 2026-10-10 |
| K-02 | `join_probe` 报 `WORKSPACE_JOIN_PROBE_FAILED`：当前引擎不支持（仅多线程计算引擎可用） | 无法事前探查关联质量 | 建表后用匹配标记回读核验（tool-chain.md） | 2026-10-10 |
| K-03 | Help 写窗口 `min/max` 支持 DATE，实际校验拒绝：“需要数值或组合日期” | 按日期取窗口极值失败 | 先 `YEAR([<日期>])` 等转数值再取 min/max，或改用 earliestTime / latestTime | 2026-10-10 |
| K-04 | `profile_project_tables` 传 `keyColumns` 不返回唯一性结论 | 无法用 Profile 验主键 | 用 countDistinct 与行数对比，或建表后回读 | 2026-10-10 |
| K-05 | detail 提示“调用 row_count 工具”，Help 引用 put_table / put_chart / dsl() 及未开放主题 | 误调用不存在的工具 | 按 tool-chain.md 的映射表转换 | 2026-10-10 |
| K-06 | 数据源表在 list 中标“数据源表”，在 detail 中类型显示“分析表” | 误以为可直接建图 | 以 list 的标注为准 | 2026-10-10 |
| K-07 | 图表 `openUrl` 为空；返回路径不带文件夹 | 无法直接给图表链接 | 用父分析表链接 + 图名 | 2026-10-10 |
| K-08 | MCP 工具描述与返回文本自称“九数云BI” | 命名不一致 | 对外一律写 FineBI Next | 2026-10-10 |
| K-09 | 图表回读“数据质量体检”的 `negative_count` 为 0，但同列 `min` 为负数 | 误判字段没有负值 | 以 min / 实际行为准，不信 negative_count | 2026-10-15 |
| K-10 | 气泡（point + size 映射）的大小范围在 Help 中没有 DSL 写法 | 对象多、画布窄时气泡严重重叠 | 先用系列透明度缓解；需要调范围时请用户在界面做样例后反读（D-010） | 2026-10-15 |
| K-11 | Help 未列出指标（`.metric`）公式可用的聚合函数；`SUM(IF(…))`、`DATESUBDATE/DATEDIF(…MAX(<日期>)…)`、日期型 `MAX(<日期>)` 指标均被类型校验拒绝 | 条件聚合、距基准日天数无法用指标实现 | 改在图表分支聚合计算 + 聚合后计算（D-019） | 2026-10-15 |
| K-12 | Help 要求主题 ID 取自 `edit/dashboard/markup-style`，但该主题在当前 MCP 版本未开放 | 无法查主题目录 | 用 Help 示例中的 `light.blue.柔彩蓝`；需要其他主题时请用户在界面设置后反读 | 2026-10-15 |
| K-13 | 回读预览中 `NumLevel.TEN_THOUSAND` 显示为英文 “Ten Thousand” | 误以为单位配置错 | 以看板目视为准（渲染为“万”） | 2026-10-15 |
| K-14 | 提交 `window().partitionBy(…).min(…)`（无 orderBy）后，保存的定义被改写为 `.orderBy(asc("<行号>"))`，结果变成按行号累计的最小值 | 分区极值错误，依赖它的标签全错且不报错 | 用子查询 groupBy + join 求分区极值（lint R8）；写后反读定义 | 2026-10-15 |
| K-15 | 年月字段 schema 为 YearMonth，但 detail 样例表头显示 STRING | 误判类型 | 以字段描述表为准 | 2026-10-15 |
| K-16 | MCP 无参数写入工具，`edit/param` Help 未开放 | 参数只能界面创建 | 用户授权后界面创建，再 get_project_asset_definitions 反读 | 2026-10-15 |
| K-17 | 看板经界面保存后含移动端样式覆盖，`get_dashboard_markup` 无法读取 | 看板失去 MCP 编辑能力 | 界面操作放最后（D-026）；已用 AI 生成副本恢复可编辑（D-028）；已于 2026-10-15 通过 report_analysis_issue 反馈；2026-10-16 实测只改交互配置（跨表联动）的界面保存不触发 | 2026-10-15 |
| K-18 | `dashboard_view` 设置绑定了参数的控件值时，引用该参数的组件仍按参数默认值计算 | 无法用 MCP 验证参数传递 | 在页面上切换控件目视核验 | 2026-10-15 |
| K-19 | `upsert_charts` 用 `Chart.from` 全量重写时，界面里设置、DSL 不能表达的配置（如气泡大小范围）被重置；`get_project_asset_definitions` 也不返回这些配置 | 只改颜色等小项也会让图形明显变样 | 优先 `Chart.edit` 只改涉及部分；必须全量重写时先问用户是否在界面调过，写后目视，必要时请用户在界面恢复（D-031） | 2026-10-19 |
| K-20 | `dashboard_view` 模拟跨表联动时，条件也作用到目标表上分支挂的图（含参数驱动指标卡），界面上这些图实际不受影响 | 误判联动范围 | 跨表联动以界面点击实测为准 | 2026-10-16 |
| K-21 | 看板保存后文档被平台规范化（补布局盒、改 padding、拆节点）；未写 `font-weight` 的文本保存后变为粗体 | 沿用旧文档的 edits 整批不生效；说明文字意外加粗 | 每次保存后重读再 edits；文本显式写 font-weight | 2026-10-16 |
| K-22 | `.conditionalFormat` 挂在 `metric(...)` 上报 “Not supported yet. Agg”；在同一次 `Chart.from` 里对分支字段写条件格式校验失败 | 指标卡无法直接按指标着色 | 对比值在分支里算成字段；先 `Chart.from` 建图，再 `Chart.edit` 追加条件格式（lint R10，D-036） | 2026-10-19 |
| K-23 | `NumberFormatConfig.number(n, NumLevel.TEN_THOUSAND, "万")` 渲染为“万万” | 单位重复 | 后缀写“元”（lint R9） | 2026-10-19 |
| K-24 | `Chart.edit` 只写一条 `numberFormat` 时，同图其他字段的数字格式被清空 | 比率等变回小数 | 增量编辑时重述该图全部 numberFormat | 2026-10-19 |
| K-25 | 系列上 `encode("label", metric(...))` 的数据标签不套用指标的百分比格式 | 标签显示小数（如 0.94） | 目视确认；去掉标签改用 tooltip / 参考线，或在说明中注明 | 2026-10-19 |
| K-26 | 看板「预览」首屏后图表仍在动画加载，约 20 秒后才是最终图形 | 过早截图误判图形或截断 | 目视至少等待 20 秒再截图 | 2026-10-19 |
| K-27 | 公式里 `YEAR(@<年月参数>)` 报“date 应为年月日时分秒 / 年月日类型”，年月型参数不能直接取年份 | 年度类图表无法直接跟随年月参数 | 暂时固定年度并在标题写明；需要联动时另行验证写法 | 2026-10-19 |
| K-28 | 写表后 operation 长时间停在 RUNNING「The table update status has not been generated yet」；此时详情显示 READY、单图回读有数，但放进看板显示「预览失败」，dashboard_view 报 INTERNAL_ERROR。之后新建或修改的表也排队卡住 | 看板新图全部取不到数，易误判为图表或看板配置错 | 写表后等 operation 到 SUCCEEDED 再建图、进看板，不连续快速提交；卡住时不新建表重试，告知用户。经用户同意后，在上游表加一个无效字段触发血缘更新，再删除（D-038） | 2026-10-21 |
| K-29 | 指标（`.metric`）公式里引用 `@<参数>` 被拒：“不在 pipeline 输出列中或类型不匹配”；用参数在多个指标之间切换同样被拒 | 指标不能随参数切换 | 在分支步骤里按参数取值（取值、取目标各一步），指标只写一个（lint R12） | 2026-10-24 |
| K-30 | 跨表联动：同一组件多条联动不能重名；交叉表作源时只有第一级行维度可传，下钻层级不可传；选项来源为“组件字段”的筛选器不能级联 | 下级层级无法联动其他板块；筛选器无法级联 | 下级层级的筛选交给全局筛选器；筛选器各自独立 | 2026-10-24 |
| K-31 | `RELATIVE_DATE` 只能用在 filter，写进 formula 被拒 | 相对日期边界写不进公式 | 公式里用 `TODAY()` 与 `MONTHDELTA` 等拼出边界（lint R13） | 2026-10-24 |
| K-32 | 反读得到的 `new NumberFormatConfig(FormatType.…)` 原样回写报 `FormatType is not defined` | 增量编辑重述数字格式时失败 | 改写为 `NumberFormatConfig.number(…)` 等工厂方法（lint R11） | 2026-10-24 |
| K-33 | 故事板 Markdown 中，表格之后的有序列表从 1 重新编号 | 编号不连续 | 表格后的条目改用无序列表，或在界面调整 | 2026-10-26 |
| K-34 | 编辑器打开看板时弹「发现未保存更改：放弃 / 恢复」，点「恢复」会用旧草稿覆盖 MCP 已保存的版本 | MCP 改动被静默回退 | 不点，告知用户；改版前重读 Markup 核对（verification.md） | 2026-10-24 |
| K-35 | 动态字段（`dynamicField`）的切换控件在 Markup 和交互增强 Help 里都没有写法；界面里是下拉框的「绑定参数 → 动态字段」 | MCP 建不出可切换的动态指标 | 用户授权后在界面绑定，放在看板最后一步（D-044） | 2026-10-28 |
| K-36 | 「绑定参数 → 动态字段」列表只显示字段名，不显示所属图表；多张图同名的动态字段无法区分，已绑定的会从列表消失 | 容易绑错图 | 每张图的动态字段起不同名字（D-044） | 2026-10-28 |
| K-37 | 控件绑定动态字段后，`get_project_asset_details` 只列出控件，不显示绑定了哪个动态字段；图表定义也不变 | 无法用 MCP 核验绑定是否正确 | 在看板「预览」里切换取值，看对应表是否变化 | 2026-10-28 |
